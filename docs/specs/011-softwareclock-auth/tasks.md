# CU0 — Tareas y evidencia

- [ ] **T1 · CA4.** Cerrar política de arranque. Probar archivo ausente, sin permisos, mal formado y campos inválidos, además de carga válida. Confirmar el montaje privado y el acceso con la identidad de ejecución.
- [ ] **T2 · CA1, CA3, CA4 y CA7.** Obtener documentación del proveedor o ejecutar pruebas autorizadas de solo lectura. Identificar tipo y valor de éxito de `code`, rechazo de credenciales, rechazo del Bearer y diferencia con permiso insuficiente. Validar expiración y revocación con evidencia del proveedor antes de automatizar su detección. Confirmar límites, `Retry-After` y efecto de emitir un segundo token antes de operar más de un proceso. Registrar solo entorno, fecha, ruta sin parámetros y clasificación verificada, con códigos permitidos. Evitar provocar saturación o revocar un usuario activo para ensayar.
- [ ] **T3 · CA1 y CA2.** Construir transporte y autenticación compartida. Con proveedor simulado, contar Basic/Bearer, comprobar origen y bloqueo de redirecciones. Cubrir HTTP 200 con error, cuerpo inválido, token ausente o con controles y respuesta demasiado grande. Comprobar primera lectura, reutilización por tres consumidores, reinicio y autenticación compartida con fallo y recuperación posterior.
- [ ] **T4 · CA2–CA4.** Usar barreras y promesas controladas para probar rechazo simultáneo, rechazo tardío, mismo token textual en nueva generación, cancelación de un solicitante y segunda denegación sin bucle. Simular 403 genérico, señal desconocida, timeout en cabeceras o cuerpo, red caída, 5xx y 429 en ambas etapas. Con reloj inyectado, verificar presupuesto, pausa, `Retry-After` válido e inválido y reanudación tras pausa.
- [ ] **T5 · CA5 y CA6.** Inyectar sentinelas ficticios para usuario, contraseña, Basic codificado y Bearer en headers, mensajes, cuerpos, excepciones anidadas y errores de arranque. Capturar respuestas, logs Fastify, eventos y trazas del transporte, métricas y stderr. Afirmar ausencia de cada sentinela y revisar Compose y artefactos de frontend para confirmar ausencia de secretos. Usar un consumidor de prueba para comprobar que el fallo externo conserva sesión y estado local. Repetir en los puntos de entrada reales cuando cada consumidor exista.
- [ ] **T6 · CA4–CA7.** Ejecutar formato, lint, tipos, unitarias, build y control del contrato usando los scripts vigentes. Ensayar rotación con fixtures. En una ventana autorizada, comprobar arranque, egress HTTPS y una lectura real tras rotación. Separar evidencia local, simulada y real en la entrega.

**Evidencia de partida.** Maxi comprobó el camino Basic/Bearer de una lectura. Esta entrega documental no ejecutó casos simulados ni autenticación real. El proxy del entorno impidió consultar Swagger. Ver [hallazgos](../../technical/softwareclock-api.md).
